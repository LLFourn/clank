# license-and-attribution
# Clank is 0BSD, and says so everywhere it ships

## Why

RELEASE-CHECKLIST.md §1 `license-and-attribution`. There is no LICENSE
file and no crate declares a licence. Lloyd chose 0BSD (§0, 2026-11-05).
Every channel (crates.io, GitHub and website binaries) needs the licence,
and the binary embeds vendored web assets, so their notices have to
travel with it.

## What changes

- A `LICENSE` file at the root containing the 0BSD text, with the
  copyright line "Copyright (c) 2026 Lloyd Fourn".
- Every `crates/*/Cargo.toml` declares:
  - `license = "0BSD"`;
  - `description`;
  - `repository = "https://github.com/LLFourn/clank"`.

  Shared values go through `[workspace.package]` and `*.workspace = true`.
- **Rust dependency notices are generated by `cargo-about`,** a
  dedicated tool that reads the locked dependency graph and each crate's
  own licence files. It is pinned in `scripts/notices/` and configured
  by:
  - `about.toml`: accepted licences (the same set as `deny.toml`);
  - the release targets `aarch64-apple-darwin`, `x86_64-apple-darwin`,
    `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`;
  - normal dependencies only (no dev or build dependencies), with the
    features the release builds use.

  The output is `crates/cli/notices/rust-dependencies.txt`, checked in.
  For each package it gives:
  - name, version and source (the crates.io URL for that version);
  - the licence branch chosen for an OR expression, and every part of an
    AND expression;
  - the full licence text, with the crate's own copyright and
    attribution where its licence file carries one;
  - the crate's NOTICE file content, when it ships one (Apache-2.0
    section 4).

  For MPL-2.0 crates such as `uluru`, the entry also states where the
  covered source is available (MPL-2.0 section 3.2): the crates.io
  download URL for that exact version.
- `THIRD-PARTY-NOTICES.md` at the root holds the vendored assets' notices
  (`crates/web/assets/vendor/*.LICENSE`, `book/fonts/OFL-*.txt`,
  `book/vendor/asciinema-player/LICENSE`) and points to the generated
  Rust file.
- **Everything ships with the binary.** `clank licenses`, a hidden
  command, prints both the vendored-asset notices and
  `rust-dependencies.txt`, embedded with `include_str!`. So does a
  standalone downloaded binary. Release archives (`release-binaries-and-
  installer`) also include LICENSE and both notice files. Each published
  crate's `include` list carries them too, so `cargo package` contains
  them.
- **Freshness.** `scripts/notices/generate.sh` regenerates the file, and
  `scripts/notices/check.sh` regenerates into a temp file and fails on
  any difference. CI runs the check. A dependency added or bumped
  without regenerating fails CI, even when its licence is already
  allowed.
- `deny.toml` with an allow-list of licences, and a `cargo deny check
  licenses` step in `.github/workflows/ci.yml`. The allow-list must admit
  everything `cargo metadata` reports today, including MPL-2.0 (`uluru`),
  `Apache-2.0 OR GPL-2.0-only` (`self_cell`), CDLA-Permissive-2.0 and
  Unicode-3.0. Anything else fails CI.
- README: a short Licence section.

## Acceptance

- `cargo metadata` shows `license = "0BSD"` for every workspace crate. An
  `it` test fails if any workspace manifest lacks it.
- `cargo deny check licenses` and `scripts/notices/check.sh` pass
  locally, and CI runs both. The `ci_workflow` gate asserts both steps
  are present.
- `clank licenses` output contains:
  - each vendored asset's licence, checked by a unit test against the
    vendor directories, so a new vendored file without a notice fails;
  - Tokio's MIT text with its copyright line;
  - `unicode-ident`'s chosen branch and its Unicode-3.0 part;
  - `uluru`'s MPL-2.0 text and its source URL.

  These are representative assertions on the embedded text.
- **Freshness mutation.** Edit `rust-dependencies.txt` to drop one
  package, and `check.sh` fails. Bump a locked dependency's version in a
  scratch copy of `Cargo.lock` and run the check against it, and it
  fails.
- `cargo package -p <main crate> --list` includes LICENSE and both notice
  files.
- RELEASE-CHECKLIST.md marks the item done, with evidence.
