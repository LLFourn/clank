Chapter 7

The remote

Drive a running team from a browser or a phone: watch every agent’s terminal, type to one, answer its question, queue the next plan. It is experimental, and it is very powerful.

Experimental, and as powerful as your terminal.

A remote session can type into your agents, and your agents can run commands on your machine. Treat the token, the one-time links and the browser session as keys to your shell. Its behaviour and setup may still change between releases.

What it gives you

The remote page shows the team as clank tui sees it: each agent’s pane, terminal and transcript, live. From it you can send an agent a message or stop its turn, queue or stash plans, manage the roster, answer blocks, reopen a closed pane, and upload a file to the repo’s machine.

Switching it on and off

The remote belongs to the repo’s running clank tui. In the TUI, the remote row under the agent list is the switch: Space on the row, or r from the log view. From a shell, ask the TUI to do the same:

clank remote on
clank remote status
clank remote off

On while already on, or off while already off, changes nothing. Switching off, or closing the TUI, stops the host the TUI started.

The default host and its door

By default the TUI starts its own host process, clank-web-cloudflare, on a port the repo remembers, and sends your browser in. The page sits behind a door, and the key is one token. Press Enter on the remote row to open the remote page, which prints the token. Paste it into the door once on each device.

  • The token is minted on first use and kept at user level, in ~/.clank/config.json under remote.token. It is the same for every repo’s remote on this machine and survives restarts. t opens the token page, where Enter or x rotates it, which ends every session it opened.
  • One-time links make pasting unnecessary. o on the row opens your browser through one. p shows one as a QR code for a phone’s camera. Each link works once, within five minutes.
  • Sessions last thirty days and are stored hashed in ~/.clank/remote-sessions.json. s opens the sessions page, which lists them. Backspace revokes the selected one, and its stream ends at once.

Reaching it from a phone: tunnels

A phone reaches the default host through a tunnel. With no tunnel and no existing host configured, the row reads not configured and the switch refuses. Configure the tunnel once, in ~/.clank/config.json under remote.tunnel:

{"provider": "quick"}
No account, no domain, nothing to install. You get an ephemeral Cloudflare quick-tunnel hostname, handed out each time the tunnel starts. Start here, and read the security note first.
{"provider": "command", "run": […]}
Any program that forwards the port, with {port} substituted into its argv. clank reads the public hostname from what the program prints, and "url_contains" picks the right line when it prints others first. Give a "url" when the hostname is yours, such as a named tunnel on your own domain. clank then claims it before the program starts.
"remote": {
  "tunnel": {
    "provider": "command",
    "run": ["your-tunnel", "--to", "localhost:{port}"],
    "url": "https://clank.example.com"
  }
}

One TUI holds a hostname at a time, and a second is told whose it is. The address reaches the remote row only after the TUI has reached its own remote through it.

Attaching to a host you run

Instead of the default host, a repo can attach to a host operated separately, for example on a server you control. Put this in the repo’s gitignored .clank/config.json:

"web": {
  "attach": {
    "endpoint": "wss://host.example/connector",
    "session": "team",
    "credential": "connector-credential-from-your-host",
    "browser_url": "https://host.example/team"
  }
}

Turning the remote on then connects outward to that host and publishes this repo’s session. The host never receives a repo path. Turning it off detaches the repo and leaves the host running. The host owns browser login, so the token and session controls above don’t apply. Plain ws and http are accepted only for loopback. clank’s repo includes a runnable custom host with its own login and connector credential, and an embedding guide for the protocol and routes.

The security limit

phone or browser
      │  HTTPS
      ▼
Cloudflare edge      ◀── TLS ends here: Cloudflare reads all of it
      │  quick tunnel
      ▼
clank-web-cloudflare, on your machine
      │  loopback
      ▼
your clank tui  ──▶  your agents’ panes

Through a Cloudflare tunnel, Cloudflare can see everything.

Cloudflare’s edge terminates TLS. Everything that crosses it is readable there: the terminal stream, your keystrokes, the one-time links and the session cookie. That is exactly the access a session has. The remote is therefore only as private as your trust in the tunnel provider.

A tunnel or host you operate yourself avoids this. Use your own TLS reverse proxy or encrypted tunnel to a host you run, with the command provider or web.attach.

The same reasoning applies to any tunnel provider: whoever terminates TLS sees the session. Never put a token, a link or a QR code in a screenshot you share.
