Chapter 8

How it works

A short tour of the machinery underneath, for anyone who wants to know why they can trust it.

The monitor

Each repo has one monitor, a background process the first clank wait or clank tui starts when none is running. It exists because watching is per repo, while delivery is per agent. Before it, every parked wait and every TUI watched and re-read the whole repo for itself, so one commit was folded many times over. Now the monitor watches once and serves everyone. It:

  • folds the repo’s state, meaning commits, plans, verdicts and the roster, into the work each agent is owed;
  • routes that work to each connected wait, which then speaks its own tool’s protocol;
  • hosts the event sources agents have configured: one producer per source, not one per wait;
  • admits one automatic wait per bound session and refuses a duplicate;
  • makes the turn-end decision for every agent.

Clients speak a versioned protocol to it. A monitor routinely outlives a cargo install, so a fresh client that meets an older monitor negotiates for it to stand down rather than being served by a build that cannot do what it needs.

The monitor is not a service. Nobody installs, starts or configures it, and it keeps nothing durable of its own. Plans, the roster, verdicts and the event inbox are files, so a monitor that goes away loses nothing that the next one cannot rebuild.

The stop hook is a messenger

When an agent ends a turn, its tool runs clank’s hook: the Stop hook for Claude Code, Codex and Grok, and the plugin for opencode. The hook decides nothing. It carries evidence to the monitor in one report on its clank wait connection: which background tasks are running, where this stop sits in the agent’s own transcript, and the session it belongs to. The monitor answers with a verdict. The hook renders that verdict in the form its tool understands, then writes back whether delivery succeeded.

Keeping the decision in one place is the point. When the hook and the monitor each decided about the same agent, linked by files one wrote and the other inferred from, the monitor could read a correctly waiting agent as idle and type a recovery prompt into it. Now there is one decider, and each tool’s hook only frames its answer.

The turn-end decision

The policy is one state machine per repo, agent and session binding. Each stop resolves to one of these:

Stay silent
Auto-mode is off; the session is no longer this agent’s; the agent is attending background work that is still running; or, for Grok, its one background wait is already armed and will carry the next wake.
Park
Nothing is owed yet. Hold the wait open until something is.
Deliver
Hand the agent its items. If the same items go out unchanged a fourth time in a row, the message escalates: ending a turn does not discharge pending work, and a real dependency on the person belongs in a block. Every item is still delivered.
Notify
Wake the agent with text that is not work, such as the one check-in owed when attended work runs past its --expect.

Every fact a decision rests on is re-checked when it is used, never cached. A Claude agent with a question open to you is recorded as asking until you answer it, and stall notices hold off while it waits.

The .clank/ layout

<repo>/.clank/
├── plans/           the active plan        committed
├── finished/        sealed plan records    committed
├── .gitignore       allows only those two  committed
├── queue/           queued plans
├── drafts/          what queue add consumes
├── config.json      roster and repo config
├── agents/<label>/
│   ├── config.json  binding, auto-mode, wait_events
│   ├── feedback/    a reviewer’s verdicts
│   └── events/      the inbox
├── blocks/ stash/ cache/ zellij/ html/
└── worktrees/ clones/   forks

What is committed and what stays local

Only plans/, finished/ and the managed .clank/.gitignore are committed. Those are the record. Everything else is per-checkout working state: the roster, each agent’s binding and inbox, the verdicts, the queue, drafts, caches and forks. Your roster is yours, and a collaborator who clones the repo brings their own team.

At user level, ~/.clank/config.json holds your agent library, saved teams, defaults such as auto-mode, and the remote’s settings. The skills and hooks clank setup installs live in each tool’s own directory, such as ~/.claude/, ~/.codex/ and ~/.grok/.

Because a rebase or an amend changes commit ids, the post-rewrite hook clank init installs moves each verdict to its commit’s new id, so review survives a history rewrite.
